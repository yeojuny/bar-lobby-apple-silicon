# Module 04 detailed source design — compact UBO CPU State admission

Status: exact small source capsule is feasible, pending root design approval and CPU/syntax qualification. Active source, fixtures, builds and apps remain unchanged. No GPU/native/FPS result is claimed.

## Exact scope and source changes

Change only `MVKCmdPushDescriptorSetWithTemplate` in `Commands/MVKCmdPipeline.h/.mm`. Under `MVK_BUILD_METAL4_FOUNDATION`, override `getMetal4RecordPolicy()` to return State if and only if `_compactUniformWriteCount > 0`, otherwise Deferred. Before the compact branch calls `getState().pushDescriptorSet`, call `retainMetal4VulkanState(_pipelineLayout)` when `isUsingMetal4()`. The existing helper itself retains only while `_metal4PreparedRecording` and deduplicates owners. Keep generic/failed/mixed captures Deferred, and leave capture contents, template ordering, pipeline/set validity, buffers, ordinary direct push, render/query/barrier policy and M3 behavior unchanged. Update the stale capture comment that says it never admits early recording.

No wider early-admission class is added. State does not create a native pack on its own: addCommand stages State until useful immediate work or a complete staged pass triggers beginMetal4PreparedRecording. The existing gate is native M4, primary, one-time, non-simultaneous use. Once an earlier Deferred occurs, this change cannot restart early recording.

## Data and address timeline

1. setContent retains pipelineLayout, resets compact count to zero, and invokes captureUniforms. Capture preflights all singleton UBO entries, the exact push set/bind point, target type/count, ranges and overflow before reading caller data. Success owns normalized VkDescriptorBufferInfo and VkWriteDescriptorSet arrays in `_pData`; ordered duplicate writes and array-element targets are retained. No UBO data bytes are read. Failure/non-admission leaves count zero and the generic fallback route.
2. compact encode consumes the node-owned infos immediately into the encoder-owned `_pushDescData`. `mvkPushDescriptorSet` dispatches to CPU layout OneID2Meta for buffers. That production case calls `MVKBuffer::getMTLBuffer`, adds getMTLBufferOffset to info.offset and records the bounded range. Therefore native object/offset interpretation really DOES move to the early encode point. It is not postponed to queue submission.
3. `MVKBuffer::getMTLBuffer` returns its existing native buffer, creates a heap buffer once under its lock, or returns its bound DeviceMemory native buffer. For the supported valid already-bound resource lifetime, these identities remain stable. DeviceMemory map/unmap/flush do not replace an existing native buffer. Host coherent writes use its current contents; managed memory retains its ordinary explicit flush requirements. Lazy construction can occur earlier and can fail earlier, which is an effect/timing change; no new host-data snapshot is introduced.
4. When the actual draw/dispatch prepares binding, it still uses current live-list checks and fresh recording retention/residency in bindMetal4Resources/Metal4BindingSink. Native work still reads the same buffer contents at execution; a legal host update after vkEnd and before submission remains visible under the existing host visibility/synchronization contract. No mapped data is copied into uploadBytes by this change.

Invalid/unbound buffer use, destroying/rebinding referenced storage before its valid recorded use, unsupported sparse rebinding, and unsynchronized concurrent updates are not admitted as new supported behavior. This port explicitly rejects vkQueueBindSparse. The design does not claim equality after arbitrary synthetic replacement of a buffer's native identity; such a future supported identity-changing operation would require Deferred admission or a new identity/refresh contract. External/imported memory still uses its original external ownership/synchronization; this module adds no stable proof bypass.

## Layout, cancellation, Ended and fallback ownership

The command node owns pipelineLayout until its next setContent/destruction, but an early-encoded node may be returned to the pool and reused immediately. An encoder-independent retain is therefore mandatory before compact encode. The retained pipelineLayout transitively retains descriptor-set layouts; encoder teardown releases its deduplicated owners. Push CPU bytes are copied into encoder-owned storage, so pooled `_pData` reuse does not corrupt the state. The node does not need to outlive the encoder after transfer except when the existing leading timestamp fallback explicitly owns it.

clearMetal4PreparedRecording disposes the prepared encoder before resetting its context/submission and releasing replay ownership. Reset/cancel must release both node layout ownership and encoder ownership exactly once; no queue adoption or query availability can be fabricated by destroying an unsubmitted recording. Ended cancellation continues through SubmissionState's existing cleanup and allocator-use policy. No changes to Q/R, liveUse, counters, GPU completion or notification gates are proposed.

A state-only prefix, including timestamp plus compact State with no real work, remains ordinary staged nodes without native allocation. Once useful work prepares the leading timestamp, `_metal4RetainPreparedReplay` preserves every original prefix node. At actual submit, timestamp activation happens after earlier query resets. A deferred-copy conflict rejects activation and restoreMetal4PreparedReplay restores original prefix before suffix, clears preparation, then ordinary replay re-encodes the compact push at the original order. This is compatible with both the old replay vector and module 03's owned chain. Retaining the layout before compact encoding does not publish query availability; it is released when the cancelled encoder is destroyed.

A later query/reset/copy/helper still returns Deferred and pauses the prefix. The existing same encoder resumes the suffix at submission, or the leading timestamp fallback restores the whole sequence. Query generation capture, completed handlers, pool ownership and mandatory GPU gates remain untouched.

## Exact parent and composition contract

R and Small have identical MVKCmdPipeline.h/.mm before this module. Module 02 changes the static descriptor-bind predicate in the same .mm, but does not touch compact class/encode. Generate baseline -> 04 and 02-postimage -> 02+04 variants for module 04; generate the matching 04 -> 04+02 stage for module 02 only if root explicitly owns that manifest update. Verify in memory that applying the two disjoint transforms in either order produces identical bytes. Header transformation is common in all variants. Pin every preimage/postimage/forward/reverse patch, including combined .mm SHA; do not fuzzy-apply a baseline-only patch to an already modified shared file. All header dependents require a fresh build at activation.

## Source-derived CPU preparation plan

Use the actual postimage captureUniforms, setContent, encode and policy body; compare the before implementation's capture/encode outputs. Extract the production OneID2Meta buffer conversion case and actual mvkPushDescriptorSet/state push bodies, mocking only other unused layout branches, native object/storage wrappers and the encoder owner container. Identify these extraction/mock boundaries in the receipt. No Metal device or queue is needed.

Cases: sparse caller offsets and unaligned inputs; singleton stride zero/short/long; duplicate targets/order; array-element target; empty/nonpush/nonUBO/mixed/overflow/generic fallback; count reset on pooled reuse; smaller retained capacity; Foundation OFF and M3 unchanged; State vs Deferred admission; no native pack for state-only; known native buffer pointer/offset/whole-size range; exact match between early and late CPU descriptors; mutate underlying bytes after early encode and after simulated Ended, ensure execution-style reads see latest value; overwriting input infos after capture must not redirect; overwriting command `_pData` only after encode must not alter copied CPU descriptors; layout refs survive node pool reuse, then release once on teardown/cancel; deduplicated repeated compact states; prepare failure and timestamp-activation reject restore prefix/suffix order; late query/unknown commands remain Deferred. Lifecycle mocks test the production control bodies they actually extract; do not claim actual native query activation from a simulated scheduler.

## Required later actual-path evidence and limitation of existing fixture

The existing `compactUniformSnapshot` already covers normalized metadata, caller-data overwrite, mapped bytes changed after vkEnd, cancellation/reuse and mixed fallback. However it calls ordinary SSBO push before the compact push. That first push is Deferred, so the new compact State admission will not exercise its early route there. Merely rerunning that existing case cannot qualify the new route.

At activation, extend an existing prepared Vulkan fixture narrowly: regular set0 contains the SSBO output, compact push set1 contains singleton UBO, with accepted pipeline/static bind state, then dispatch. Assert actual prepared prefix before vkEnd; change UBO contents after vkEnd; submit and check the latest value and guards. Include early prefix cancellation, pooled node/layout reuse, timestamp+compact-only no-work, leading timestamp with useful work, deferred-copy activation rejection restoring prefix before suffix, late query and legacy M3. Existing CPU/syntax may prepare the capsule now, but native path correctness, actual early BAR reach and net FPS benefit remain open. The change shifts work earlier and may create additional prepared work; no source-only net-time/FPS promise is made.

Reviewer execution: source/evidence reads and these two design files only. No active writes, compiler/test/GPU/app/benchmark execution, new agents, remote writes or cleanup.
