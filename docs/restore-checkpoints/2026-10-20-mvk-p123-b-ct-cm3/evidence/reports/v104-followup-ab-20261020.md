## 적용 범위와 근거

초기 검토의 호출 간/호출 내부 용량 재사용안 대신, 각 batch 안의 작은 배열 저장 방식만 바꿨다. 반복 호출이나 동일 prepass 내 여러 batch가 없어도 작은 batch마다 적용된다. 두 컨테이너 크기는 합계 368바이트이며 내부 데이터 공간은 336바이트다. 기존 std::vector 객체 합계는 48바이트였다. 5개 이상은 채우기 전에 최종 용량을 힙에 확보하므로 성장 중 추가 복사도 생기지 않는다. 256개 상한과 기존 묶음 처리·실패 경로를 유지했다.

과거 R45 실제 BAR interior 자료에는 restart batch 3,960회와 해당 draw 17,160개가 있다. 각 batch의 최소 크기가 2이므로, 이 중 최소 880회는 크기 2~4였음을 계산할 수 있다. 이는 과거 BAR 사용 근거이며 현재 후보의 발생 빈도나 FPS 개선량은 아니다. 근거 파일은 artifacts/validation/metal4-r45-seths-20261004/analysis.json이다.

CPU 임시 배열에서 submission 소유의 immutable GPU 공간으로 복사하는 기존 uploadBytesRange 경로는 유지한다. 업로드 복사 횟수를 줄였다고 주장하지 않는다. 출력 배열, GPU 자원 보유·반환 시점, barrier, 동기화, render pass, 다른 recording과의 공유는 바꾸지 않았다. Mesa의 변환 중간 버퍼 및 미관측 indirect 경로도 변경하지 않았다.

## 검증

- 실제 활성 MoltenVK 빌드는 변경 파일 재컴파일과 재링크만 수행해 통과했다.
- 기존 GPU prepass 검사 29/29 통과, Metal API Validation 사용. 창·게임 실행 없음.
- 실제 production 선언과 record 구조를 읽어 구성한 CPU 확인은 크기 2·3·4·5·8·256에서 초기화, byte 일치, 정렬, inline/heap 경계를 ASan·UBSan으로 통과했다. 별도 CPU 검사 준비 중 include 경로 누락 3회를 기록했고, 실제 production 빌드의 전체 include 설정을 사용해 해결했다. 제품 빌드 실패는 없었다.
- 비교 기준의 57개 핀 중 의도한 MVKCmdDraw.mm만 변경됐다. 나머지 56개 앱·엔진 소스·빌드 설정·기존 fixture 핀이 일치한다. 전체 트리 재인벤토리 결과로 확대하지 않는다.

B는 현재 로컬 MoltenVK 빌드에만 있다. 앱 패키징·설치·발행·추가 FPS 게임 반복은 하지 않았다. A의 제외 판정은 선택된 콘텐츠의 정적 검색 범위이며 미래 콘텐츠나 동적 이름 생성까지 증명하지 않는다.
