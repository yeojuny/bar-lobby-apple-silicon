# Recording-local group locator: independent source review

No actionable source defect was found. The same narrow class change is suitable for validation on both R and R+D+E1+E2+E3. This is source/fixture review only; build, test and package acceptance remain pending. The reviewer did not edit product/fixture/build files or execute builds, tests, GPU workloads, apps or benchmarks.

Both frozen preimages have the exact same GroupCache body. Each next header independently equals its preimage with only that class replaced by the common after.inc. At read time active Combined header is `a3bde09f61f9ec0b0f1f366eb51c079a60d439e7eacf0b0f8c5086cec219bbbc`; R-next is `dfc0ddbd4f7296542306c1a6ce72d1a1282a44dc807d98cdc187771a14be0627`. Frozen input and fixture hashes are recorded in the JSON.

The six recent slots contain only script and mapped Entry address. The map remains authoritative and keyed by script; a location hit does not bypass stamp equality, validity, sameIdentity, drawable epoch, covered binding revisions, weak resource proof validity, stableStamp callback, or residual/partial-plan handling. Same-script updates from another stage remain visible through the same node, and an old stage memo still reaches the complete original stage-aware validation. Stages outside0–5 take the ordinary map lookup. Misses do not become negative cache entries.

Stored mapped addresses remain stable through unordered_map insertion/rehash. This class has no individual erase path. clear resets all recent pointers before destroying map entries. Explicit default construction and deleted copy/move prevent pointers becoming aliases of another recording's map. Actual production ownership places the cache in a State already containing a mutex; callers receive references and no cache transfer path was found. No native ownership, residency, cross-recording reuse or synchronization is added. The128-entry admission cap, update-existing behavior, before/after stability and proof identity checks are unchanged.

The actual-header CPU fixture compares complete/partial outcomes and revision/stableStamp callback counts with the exact frozen class. The frozen reference differs only by class name. The operation-count variants likewise differ only by class names and the test CountingHash; the reviewer independently reconstructed these transformations. Targeted cases exercise map growth/rehash with an old stage memo,128-entry overflow and existing updates, same-script stage overwrite, stage6/31/UINT32_MAX fallback, clear/reuse and metadata release, weak-proof expiry, revision and unstable refresh rejection, partial residuals, changed incarnation, drawable epoch and malformed stamps. There is also a deterministic50000-step trace and static noncopy/nonmove assertions. The six-stage1200 hot lookup observation is confined to extracted test classes, with no product counter.

The implementation intentionally does not seed the memo during a fresh insertion; a later first lookup fills it. This is a warm-up cost, not a safety defect. Six uint64_t/pointer pairs add96 bytes on the target64-bit ABI, and lookup/clear branches have a cost. Fewer hash invocations therefore do not by themselves establish FPS, latency or memory benefit. The fixture is appropriate for metadata invariants and operation counts, while the planned selected native sequential-recording and Vulkan revision/layout cases must supply their own actual execution evidence for each variant. No full-game, race-freedom, MP or universal GPU acceptance follows from this source review.
