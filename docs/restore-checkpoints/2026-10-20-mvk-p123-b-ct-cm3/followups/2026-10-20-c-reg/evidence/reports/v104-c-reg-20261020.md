# C-REG 구현과 현재 후보 대비 성능 비교 — 2026-10-20

**완료: C-REG 구현·독립 검수·관련 검증을 통과했다. 요청한 전체 화면 역순 비교에서 Metal4 평균 FPS +3.05%, Metal3 −0.87%를 관찰했다.** 각 앱/백엔드 두 번의 결과이며 무위험·모든 부하에서의 순이익 또는 통계적 유의성을 보증하는 결과는 아니다.

사용자 요청: “C-REG부터 구현하고 검증해봐. 지금 후보랑 전원 연결·절전모드에서 같은 조건으로 Metal3·4 성능 비교해서 표로 줘.”

## 구현

기존 누적 후보 P1/P2/P3+B+C-T+C-M3 위에 C-REG 하나를 추가했다. 이미 버퍼·텍스처 타입을 아는 descriptor/vertex 등록 및 render attachment/visibility 호출부에서 타입을 전달한다. `addResource`의 첫 등록에서 분류한 결과도 residency lease에 전달하여 재분류하지 않는다. 일반 `addResource`와 공개 `lease` 진입점은 그대로 사용할 수 있다.

수정 제품 파일은 `MVKMetal4Submission.h/.mm`, `MVKCommandEncoderState.mm`, `MVKCommandBuffer.mm` 네 개다. 기록마다 실제 retain/residency를 획득하며, device 검사·heap/parent view 조회·drawable generation/ownership·mutex·GPU 완료까지의 보유는 유지한다. 타입 정보가 소유권이나 ordinary texture 여부를 증명한다고 취급하지 않는다. allocator·barrier·pass 분할·기록 간 소유권 정책은 변경하지 않았다.

현재 후보와 새 후보 모두 표시 버전 **1.0.3**을 유지한 로컬 **v1.0.4 후보**다. 공식 1.0.4 배포로 승격하지 않았다.

## 관련 검증

- CPU 등록 fixture: ASan/UBSan, 410 assertions 통과. nil/foreign device/ended 상태, retain-first, 새 기록별 소유권, cancellation, generic/typed 경로, drawable 변경·포화 generation, parent-view lease를 확인했다. 미등록 자원의 첫 등록에서 texture protocol 조회는 generic 1회, typed 0회이며 residency fallback에서 재분류하지 않았다.
- 실제 Metal4 GPU: 기존 lifetime fixture에서 6개 관련 사례만 실행하여 모두 통과. generic/typed 경로 각각에서 blocked GPU copy, allocation 재등록, heap 및 texture view, caller 해제 뒤 GPU 완료까지의 lease 보유를 확인했다.
- 제품 번역 단위 3개를 Metal4 foundation OFF/ON 각각 검사: 6/6 통과. 기존 활성 build에서 incremental Release build, custom diagnostics OFF.
- 실제 Vulkan prepared-recording suite 6/6 통과. common descriptor fixture도 Metal3·Metal4 각각 6 cycles 및 graphics 검사 통과.
- 수정하지 않은 소스/빌드/검증 입력 70개 핀과 직전 후보의 간접 바인더가 일치했다. 기존 launcher HEAD/index 유지.

CPU fixture는 NSObject 장치 모형으로 실제 등록 구현을 실행한다. 오래된 R47 retirement 내부 테스트까지 포함하던 부분은 해당 모형 정의만 재사용하도록 고쳤다. R50 당시 간접 바인더와 동일해야 한다는 낡은 조건은 이후 승인된 R71/R4/R5와 맞지 않으므로 제거하고, 이번 변경에서는 직전 후보와 바인더 일치를 별도로 검증했다. 관계없는 stage-preparation cache는 reset용 대체 슬롯이므로 실제 stage cache reset 검증으로 세지 않는다. 앞선 두 fixture compile 실패 기록도 보존했다.

## 첫 비교 조건 — 창 모드 1432×902

AC 전원·절전모드 ON, Ultra·AA Off·Spring·VSync Off, 1432×902, sound off, hidden window. 기존 Seths Ravine Remake 1.3.1/BAR test-31671-ad2e1b7 장면, 고정 frame240에서 공식 900-frame benchmark를 시작한다. 각 실행은 동일한 입력의 독립 profile/빈 cache를 사용한다. CPU sampling·추가 runtime 진단은 끈다.

Metal4 순서는 기존→C-REG→C-REG→기존, Metal3 순서는 C-REG→기존→기존→C-REG다. 총 8회이며 실패하면 남은 측정을 중단한다. 종료가 확인된 해당 시험의 재생성 가능한 cache만 정리하고 앱·소스·원본 결과·로그·Markdown을 보존한다.

구현 및 검증 근거: `artifacts/validation/v104-c-reg-20261020/`. 성능 비교 근거: `artifacts/validation/v104-c-reg-performance-20261020/`. 첫 비교 8회가 완료된 뒤 사용자 지시에 따라 아래 전체 화면 역순 8회를 추가 완료했다.


## 최종 비교 — 전체 화면 설정, 표시 억제, 역순

후속 사용자 지시 “역순으로 조져봐”, “노치 제외한 전체화면해상도”, “앞에 화면만 안 띄울뿐 전체 화면으로”를 적용했다. Apple M4 Pro(Mac16,8), macOS 27.2에서 실제 화면은 논리 1512×982, 위쪽 safe inset 32다. 게임을 `Fullscreen=1`, `--fullscreen`으로 시작했다. SDL fullscreen 요청을 거부하던 기존 시험 sidecar는 이번 전용 복사본에서 요청을 실제 SDL에 전달하도록 바꾸고, hidden/fullscreen flags와 Cocoa 비표시 상태를 확인한다. create/show/raise/restore의 숨김 보호는 유지한다. 제품 앱·SDL·엔진 코드에는 이 변경을 넣지 않았다.

실제 8개 게임 로그 모두 fullscreen 설정, 창 영역 **1512×982**, safe viewport **1512×950**, Spring 카메라, Ultra·AA Off·VSync Off가 일치했다. 기본 1× drawable 정책을 유지하며 Retina 2× 렌더링으로 바꾸지 않았다. SDL은 숨긴 창의 fullscreen 의도/flags를 보유하고 실제 macOS display/Space 전환은 표시될 때까지 유예한다. 따라서 게임의 전체 화면 렌더링 경로를 사용한 숨김 비교이며, 화면에 표시된 exclusive fullscreen의 presentation 특성까지 검증한 것은 아니다.

순서: **Metal3 기존→C-REG→C-REG→기존**, 이어서 **Metal4 C-REG→기존→기존→C-REG**. 기존 앱 두 개를 그대로 사용하며 실행별 private profile과 cold cache를 분리했다. 화면 조건 변경으로 이전 1432×902 결과와 FPS를 합산하지 않는다.

| 백엔드 | 실행 앱(표시 버전 모두 1.0.3) | 1회 FPS | 2회 FPS | 평균 FPS | 실행별 p95 평균 ms |
|---|---|---:|---:|---:|---:|
| Metal3 | 기존 P1/P2/P3+B+C-T+C-M3 | 49.68 | 49.48 | 49.58 | 32.51 |

Metal4 평균 FPS는 **+3.05%**, p95 지연은 **−4.13%**다. 두 C-REG 실행(45.17/45.66)은 두 기존 실행(44.49/43.65)보다 모두 높았다. Metal3는 평균 FPS **−0.87%**, p95 **−3.20%**로 지표 방향이 엇갈리며 뚜렷한 개선으로 해석하지 않는다. C-REG가 대상으로 삼은 경로는 Metal4다.

기존 창 모드 묶음에서도 Metal4 평균은 +3.17%였으나 기존 앱 자체가 36.96→41.35 FPS로 변했다. 이번 전체 화면 묶음은 더 작은 실행 간 변동 속에서 같은 방향을 보였지만, 표본은 각각 2회이며 다른 장면·장시간 플레이·다른 Mac까지 일반화하지 않는다. FPS는 두 실행 평균의 산술 평균, p95/p99는 각 실행 percentile의 평균이며 전체 프레임을 합친 percentile이 아니다.

## 최종 검증과 정리

총 16개 실제 BAR 실행이 모두 정상 종료했다. 각 실행의 고정 900 simulation frames, 품질·카메라·장면·seed와 실제 MVK 로딩 경로/해시를 확인했다. 전체 화면 묶음 전원 관측 72개 모두 AC·Low Power ON이며 thermalState는 모두 0이었다. Metal4 네 실행은 native queue 활성과 실제 완료 제출을 확인했고, Metal3 네 실행은 native Metal4 queue 0을 확인했다.

원본/새 앱 전체 inventory, 변경 외 70개 핀, 최종 수정 6개 핀, 실제 launcher HEAD/index/status 및 사용자 profile 3개가 보존됐다. 임시 화면 보호 설정을 원래대로 복원하고 소유한 awake assertion을 해제했다. 각 실행 종료 후 private cache **96개 root, 5330개 leaf, 153,930,604 logical bytes**만 정리했다. 물리 회수량으로 환산하지 않는다. 앱·소스·raw 결과·로그·Markdown과 이전 raw MVK는 보존했다. 새 앱 설치·공식 Release/Homebrew 갱신은 하지 않았다.
